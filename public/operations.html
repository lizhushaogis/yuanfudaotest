第一次这样操作

  1. 打开自动初评页。15条题已经在里面，不用你再准备。
  2. API URL填供应商提供的兼容地址；模型名填你已开通的模型；API Key填自己的密钥。DeepSeek默认地址与模型可直接修改，其他兼容服务按控制台信息填。
  3. 勾选本次调用确认。完整一轮最多30次请求，供应商按实际调用计费；这里不承诺固定金额。
  4. 点“开始15题自动初评”，保持页面打开。网站会逐题生成、检查、评审。
  5. 结束后展开“发现问题”“待复核”或“失败”的题，读具体证据；点“下载报告与生成代码”保存结果。

系统到底自动做了什么？

第1题输入→请求模型生成HTML→程序检查文档闭合、脚本和外部资源线索→再次请求模型，对照四条参考标准审查代码→保存结果。然后自动做第2题，直到15题结束或被暂停。

你不需要逐题复制，也不需要逐题填写分数。15次生成加15次评审，完整一轮最多30次请求，不会自动重试。生成失败的题保留失败，不会假装拿到了产物。

API用在哪里？

生成网页和AI代码评审都使用你填写的API。本轮默认同一模型负责生成与复审，共同盲点可能让它们一起判断错。代码结构检查、保存与下载不需要额外API。

API Key只在页面内存中，不写入报告或本地存储。页面会把合成题和生成HTML送到你填写的服务，不会把连接密钥写入题目。

怎样读报告？

  • AI建议通过：结构线索满足，AI从代码中认为四项满足；仍不是实际操作验收。
  • 发现问题：结构检查或AI审查指出了不符合项，展开看原因。
  • 待复核：AI没有足够证据确认。科学争议和动态行为不能靠猜。
  • 生成/评审失败：本次请求或输出未完成，保留错误，不算通过。

本页没有自动浏览器执行器，因此不会自动点击按钮、拖动滑杆或检验重置。动态交互仍需实际复核；不能拿“代码里有reset”证明重置真正可用。报告中已明确这一限制。

先不要做什么

不要直接跑100题；不要看到“建议通过”就宣布全部功能测过；不要把合成题的结果说成真实内部业务效果。先跑这15题，下载产物与证据，确认初评是否能发现明显缺陷，再决定是否需要投入自动浏览器测试。
