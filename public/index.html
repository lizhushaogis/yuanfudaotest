MODEL CONNECTION

连接你的模型服务

要让模型根据每次的新需求生成内容，需要先运行本项目的 Node 代理。你只需要准备模型名称和 API Key；模型服务地址会按模型名称自动选择。API Key 粘贴在项目根目录的 .env 文件里，不要粘贴到网页或 GitHub。

本机按 README 启动后填 http://127.0.0.1:4173；如果你把代理部署到云端，就填云端 HTTPS 根地址。GitHub Pages 本身只提供静态页面。 这是你为代理服务设置的访问口令，不是模型供应商的 API Key。
你只需要提供两项LAB_MODEL=你的模型名称LAB_API_KEY=你的模型 API Key文件位置：项目根目录 .env。其余代理地址、允许来源和网页配置由项目默认处理；保存后运行 node --env-file=.env server.mjs。
ABOUT THE PROJECT

从想法到实验的六步

这个工作台把一条教学需求变成一个可检查、可运行、可下载的交互项目。本地演示可以直接运行；要让模型参与新项目生成，需要连接 API。你不需要先懂提示词工程。

01 · 输入需求

写一句“给谁学、学什么、希望学生做什么”。

02 · 结构化

提取主题、目标、条件，并判断适合的交互类型。

03 · 生成方案

生成探究问题、观察反馈、结论和状态机。

04 · 校验落实

检查主题相关性、条件数量、状态转移和不能发生的错误。

05 · 运行预览

在网页里点击开始，逐项观察反馈并完成实验。

06 · 导出交付

下载项目 JSON、Markdown 文档、Prompt 和独立 HTML。

HOW THE WORK IS DONE

这项工作不是“让 AI 随便写一页网页”

先把教学目标拆成可观察的条件，再把条件落实为按钮、反馈、完成条件和重置规则；最后用同一个项目 JSON 同步方案、文档、资源和预览。模型负责理解和提出草案，系统负责结构校验、主题相关性检查和可执行预览，人工负责学科准确性审核。

角色教育交互设计助手任务把需求变成项目草案上下文学习者、主题、目标、条件约束只用已实现交互，不编造数据格式固定 JSON 字段验收主题相关、可操作、可重置
提示词工程，用大白话说：不是写一句“帮我生成”，而是把角色、背景、任务、边界、输出格式和检查标准一次说清楚，让模型稳定地产出能被程序接住的结果。
本地生成器与模型模式

本地生成器会根据新的自然语言需求推断交互类型，并生成项目 JSON、文档和网页；模型模式通过代理让模型补充需求理解。两种模式都经过结构校验，实验为概念示意，正式课程仍需学科审核和用户测试。
