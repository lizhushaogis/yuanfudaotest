# 知行实验室 · AI 交互实验工作台

把一条新的教学需求，生成一份可审核、可运行、可导出的教学交互项目。

这是基于通用教研生产流程独立实现的公开演示。示例文案、图形和代码在本仓库重新编写，不包含原单位文件、内部链接或生产数据。

## 可以实际做什么

1. 用自然语言描述新的教学需求，也可以点击示例查看写法。
2. 生成器先判断交互类型（条件比较、过程模拟、分类判断、顺序探索、粒子模拟或因果探索），再生成条件、反馈、状态机和验收规则。
3. 方案、交互规格、资源清单、复现提示词和网页都从同一个 `project.json` 生成，避免文档和实现互相漂移。
4. 在预览中实际点击开始、逐项探索、查看反馈、重置和完成结论；不同交互类型会使用不同的概念图和控制方式。
5. 导出包含原始需求、结构化项目、Markdown 文档和独立 HTML 的 ZIP 交付包。HTML 可以离线打开。

生成后的每一步都可以人工修改：教学方案可改标题、目标、观察条件和反馈；交互方案可改操作类型、反馈时长与完成规则；资源清单可改文件、用途和状态；复现提示词可直接重写。点击“保存修改”会把当前版本写回项目 JSON，后续文档、下载文件和预览都读取这份新版本；点击底部继续按钮也会先自动保存当前步骤。

## 第一次运行怎么填

打开网页后，第一步只填写“教学需求”这一框，按下面的顺序写一句话即可：

```text
给谁学 + 学什么 + 学生怎么操作 + 希望理解什么
```

例如：

```text
给七年级做一个水循环探索，让学生观察蒸发、凝结和降水，最后理解水循环过程。
```

点击“生成新的交互项目”后，会依次得到教学方案、交互状态机、资源清单、复现 Prompt、动态预览网页和可下载 ZIP。学科和限制是可选补充；标题、条件和结论已收进“可选高级设置”，一般不需要填写。默认本地生成器会根据新需求推断内容；如果要让模型真正参与生成，再按下方方式连接 API。

没有配置模型时，网站使用**本地生成器**：它根据需求关键词选择交互类型，并用确定性规则生成完整项目，方便先验证产品逻辑。**模型模式**会真实调用用户部署的代理：模型负责理解新需求、补充教学表述和条件；服务端检查返回 JSON 是否有效、是否与主题相关；前端随后把模型结果收敛到受控的项目结构，校验条件数量、交互类型和必备状态。这样每次输入新的需求都会得到新的项目数据，而不是只替换标题的固定结果。

## 这项工作是怎样完成的

工作被拆成六步：

1. **输入需求**：只收集“给谁学、学什么、学生怎么操作、希望理解什么”。
2. **结构化需求**：提取主题、目标和观察条件，判断是条件比较、过程模拟、分类、顺序、粒子还是因果探索。
3. **生成教学方案**：形成探究问题、观察反馈、预期结论和适合的交互类型。
4. **落实交互规格**：把方案写成 `initial → step/selecting → feedback → completed` 状态机，规定按钮、反馈锁定、完成条件和重置规则。
5. **同步资源与提示词**：从同一份项目 JSON 生成资源清单和复现 Prompt，保证文件名、反馈文字和网页行为一致。
6. **预览与验收**：实际点击开始、条件、反馈和重置；检查主题相关性、操作可达性、键盘操作和移动端布局，再导出交付包。

同一套生成逻辑会按主题选择场景：例如“碳循环”会生成碳在植物、动物、分解和燃烧之间转移的循环图，“水循环”会生成蒸发、凝结和降水的循环图，“光合作用”会生成光照、二氧化碳和水分条件。模型返回的项目还会经过主题词相关性检查，避免把无关的固定模板塞进预览。

提示词工程用大白话说，就是把“角色、背景、任务、边界、输出格式和验收标准”一次说清楚，让模型稳定地产出程序能接住的结果。这里的系统提示词要求模型只返回固定 JSON、只使用已实现交互、不编造数据；服务端再做 JSON 和主题相关性校验，模型不是直接把任意文字塞进网页。

预览是定性概念示意，正式美术和配音尚未制作。浏览器朗读可选开启，正式课程仍需学科审核和用户测试。自定义主题使用通用图形，不会自动绘制专业实验装置。

## 本地运行

需要 Node.js 20 或以上，不需要安装第三方依赖。

```sh
npm start
```

打开 http://127.0.0.1:4173 。测试与语法检查：

```sh
npm run check
npm test
```

## 配置真实模型

网页设置里要填写的是**模型代理根地址**，不是上游模型 API Key。API Key 的准确位置是项目根目录的 `.env` 文件中的 `LAB_API_KEY=`。你可以先在项目目录启动代理：

```text
http://127.0.0.1:4173
```

这就是本机可填写的 API 地址。代理提供 `GET /api/health`、`POST /api/project/generate`，并在服务端保存真正的模型密钥。GitHub Pages 是静态托管，不能直接保存密钥或执行 Node 代理；如果要让公开网站也能生成，需要把本项目的 `server.mjs` 部署到支持 Node 的服务，并把部署后的 HTTPS 根地址填入网页。

复制 `.env.example` 为 `.env`，通常只需要填写模型名称和 API Key：

```dotenv
LAB_API_BASE=
LAB_API_KEY=粘贴你的模型 API Key
LAB_MODEL=填写你的模型名称
LAB_ACCESS_TOKEN=choose-a-long-random-service-token
LAB_ALLOWED_ORIGIN=https://your-name.github.io,http://127.0.0.1:4173
HOST=127.0.0.1
PORT=4173
```

```sh
node --env-file=.env server.mjs
```

模型供应商需要支持 Chat Completions 和 `response_format: {type: "json_object"}`。如果 `LAB_API_BASE` 留空，服务会按模型名称自动选择常见兼容地址（OpenAI、DeepSeek、通义千问、智谱、Moonshot、豆包）；服务端验证 JSON 结构和主题相关性，模型不满足约束时会提示错误，不会静默切换成模板。

公开代理使用 HTTPS（通常由托管平台或反向代理提供），按托管平台要求设置 `HOST=0.0.0.0`。公网调用必须设置 `LAB_ACCESS_TOKEN`；`LAB_ALLOWED_ORIGIN` 逗号分隔准确的允许来源。访问口令仅保留在网页内存，刷新后需要重新输入。模型 API Key 只配置在服务端，不能填写到网页、提交到 GitHub 或放入 `public/`。代理内置请求大小和频率限制，费用由配置的模型服务承担。

网页连接验证会检查代理配置；首次生成时才实际请求模型。未配置真实密钥的公开演示不能证明供应商接口已经联调成功。

## 文件如何衔接

| 文件 | 用途 |
| --- | --- |
| `public/app.js` | 自然语言需求输入、六步审核流程、模型连接与下载 |
| `public/engine.js` | 结构校验、统一配置、文档生成、HTML 和 ZIP 导出 |
| `public/project.js` | 需求归一化、交互类型推断、项目 JSON、动态预览和项目导出 |
| `public/experiment.js` | 可离线复用的概念图与状态机，反馈期间锁定操作、重置取消旧任务 |
| `server.mjs` | 服务 public 静态文件；保护模型密钥，执行项目生成请求 |
| `tests/` | 配置、导出、内容转义、代理鉴权与模型协议测试 |
| `.github/workflows/deploy.yml` | 检查成功后发布 public 到 Pages |

新需求 → 交互类型推断 → 教学方案 → 交互规格 → 场景与资源 → 动态网页 → 验收 / 导出。相同的项目 JSON 让条件名称、文档、文件名和实验行为保持一致。
